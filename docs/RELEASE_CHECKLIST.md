# 发布候选检查表

正式 `v*` tag 与稳定 Release 必须由维护者明确批准版本号和提交 SHA。Nightly 成功不会自动
升级为稳定版本。

## 发布前自动门禁

- [ ] `main` 的最终提交与候选提交完全一致。
- [ ] CI 的 Rust、Python、前端、参考播放器契约和 Windows 打包全部通过。
- [ ] Release candidate 工作流完成 NSIS、GUI ZIP、CLI/TUI ZIP 和 SHA256。
- [ ] 安装器在干净 Windows runner 静默安装，GUI 启动持续 8 秒未退出。
- [ ] 播放器真实时钟测试误差不超过 50ms；无音频设备时明确记录降级。
- [ ] 2 秒完整工作流验证分析、转录、编辑、导出和父 revision 不变。
- [ ] 10 分钟分析在门限内完成，缓存可复用且峰值工作集低于 2 GiB。
- [ ] 固定 LGPL FFmpeg、模型、Schema、第三方通知和对应许可进入包。
- [ ] 基础包不包含 `torch`、`torchaudio` 或 `demucs`。

## 人工质量门禁

- [ ] 使用用户熟悉的代表性独奏素材完成原音、instrumental、合成和路由 A/B 听评。
- [ ] 核对鼓音、弱音、滑音和局部变速场景的已知限制。
- [ ] 在参考播放器上验证兼容谱解析和虚拟调度。
- [ ] 确认钢琴卷帘编辑后的导出与画面一致，源媒体和父 revision 未变化。
- [ ] 维护者确认版本号、Release notes、许可证与发布范围。

## 正式发布授权

只有以上自动与人工门禁全部通过，且维护者明确批准版本号和目标 SHA 后，才可创建正式
`v*` tag 和 GitHub Release。任何失败或未完成的听评应阻断稳定发布，但可继续发布带明确
限制说明的 Nightly 测试包。
